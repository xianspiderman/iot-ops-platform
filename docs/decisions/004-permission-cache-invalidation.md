# ADR-004：RBAC 使用 Redis cache-aside 与双失效

- 状态：已接受
- 日期：2026-09-15

## 背景

接口权限在每个受保护请求中读取。直接 JOIN 用户、角色和权限最容易保持正确，但会把稳定授权关系重复查询；只依赖长 TTL 缓存又会使撤权延迟不可控。

## 候选方案

- 每次直接查库：最简单、即时一致，数据库读取更多。
- 本地缓存：速度快，但多实例失效困难。
- Redis cache-aside：可跨请求共享，需要设计缓存失败和授权变更窗口。
- 把完整权限固化进 token：读取少，但撤权必须等待 token 到期或维护黑名单。

## 决定

按用户缓存权限码 JSON，TTL 30 分钟；miss 时查库并 best-effort 回填。Redis 读写异常直接回退数据库。授权写入前先删除相关用户缓存，事务提交后再次删除，并注销受影响用户的 Sa-Token 会话。数据范围保持数据库直接读取，因为它参与业务查询且变更频率、读取形态与接口权限不同。

## 结果

集成测试证明 miss、hit、失效、重载和 token 失效；Prometheus 暴露对应计数。代价是变更时有额外查询和缓存操作。当前一个后端部署实例足以完成会话注销；只有多实例出现实测失效延迟时，才增加 Redis Pub/Sub 或专用授权变更事件，而不先引入消息中间件复杂度。
